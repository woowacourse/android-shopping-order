## 🚀 4단계 - 주문 & 알림

## 4단계 기능 및 작업 명세

### 결제 화면 진입 흐름 추가

- 장바구니에 담긴 상품을 최종 주문할 수 있는 결제 화면을 추가한다.
- 결제 수단 선택 및 결제 수단 로직은 구현하지 않는다.

### 결제 화면 UI 구현

- 피그마 시안을 기준으로 결제 화면 UI를 구현한다.
- 상단 앱 바에는 뒤로 가기 버튼과 `결제하기` 제목을 표시한다.
- 결제 화면에는 적용 가능한 쿠폰 목록을 표시한다.
- 쿠폰 영역에는 `적용 가능한 쿠폰` 제목을 표시한다.
- 쿠폰 영역에는 `쿠폰은 1개만 적용 가능합니다.` 안내 문구를 표시한다.
- 쿠폰 카드는 선택 상태와 미선택 상태를 구분해서 표시한다.
- 선택된 쿠폰은 체크 아이콘과 강조 색상으로 표시한다.
- 결제 화면에는 주문 금액, 쿠폰 할인 금액, 배송비, 총 결제 금액을 표시한다.
- 배송비는 기본 3,000원으로 표시한다.
- 총 결제 금액은 `주문 금액 - 쿠폰 할인 금액 + 배송비`로 계산한다.
- 결제하기 버튼은 화면 하단 고정 영역에 표시한다.

### 쿠폰 조회 및 선택 구현

- 결제 화면에서 적용 가능한 쿠폰을 조회한다.
- 쿠폰은 1개만 적용할 수 있다.
- 쿠폰을 선택하면 기존 선택 쿠폰은 해제하고 새 쿠폰만 적용한다.
- 선택된 쿠폰 정보는 결제 화면 상태에 반영한다.
- 쿠폰을 사용해도 쿠폰 데이터는 사라지지 않는다.

### 쿠폰 할인 계산 구현

- 쿠폰을 유형별로 추가한다
  - `FIXED5000` 쿠폰은 주문 금액이 100,000원 이상일 때 5,000원을 할인한다.
  - `BOGO` 쿠폰은 동일한 상품을 3개 담은 경우 1개 금액만큼 할인한다.
  - `BOGO` 쿠폰 조건을 만족하는 상품이 여러 개라면 1개당 금액이 가장 비싼 상품에 적용한다.
  - `FREESHIPPING` 쿠폰은 주문 금액이 50,000원 이상일 때 배송비를 0원으로 계산한다.
  - `FREESHIPPING` 쿠폰은 도서 및 산간 지역인 경우에도 무료 배송이 가능하도록 처리한다.
  - `MIRACLESALE` 쿠폰은 오전 4시부터 오전 7시까지 주문 금액의 30%를 할인한다.
- 할인 금액은 주문 금액을 초과하지 않도록 계산한다.

### 최종 주문 완료 처리

- 결제하기 버튼을 누르면 바로 최종 주문을 완료한다.
- 최종 주문 완료 API를 호출한다.
- 최종 주문이 완료되면 상품 목록 화면으로 이동한다.
- 최종 주문이 완료되면 장바구니에서 주문된 상품을 초기화한다.
- 주문 완료 후 쿠폰은 사라지지 않도록 유지한다.
- 주문 완료 후 상품 목록으로 이동할 때 주문 흐름이 Back Stack에 남지 않도록 정리한다.
- 주문 완료 이후 뒤로 가기 시 장바구니 또는 결제 화면으로 되돌아가지 않도록 한다.
- 주문 완료 실패 시 사용자에게 오류 메시지를 표시한다.

### 미결제 알림 설정 저장

- 설정에서 미결제 알림 기능을 On/Off 할 수 있도록 한다.
- 앱을 재실행해도 마지막 알림 설정값이 유지되도록 한다.

### 미결제 알림 예약 및 취소 구현

- 결제 화면에 진입하면 5분 후 미결제 알림을 예약한다.
- 결제 화면 재진입 또는 복귀 시 기존 예약을 먼저 취소해 중복 예약을 방지한다.
- 5분 안에 결제하지 않으면 `아직 결제가 완료되지 않았어요` 알림을 노출한다.

### 알림 클릭 시 결제 화면 이동 처리

- 미결제 알림을 클릭하면 결제 화면으로 이동한다.
- 앱이 종료된 상태에서도 알림 클릭 시 결제 화면으로 이동할 수 있도록 PendingIntent를 구성한다.
- 알림으로 결제 화면에 진입해도 결제 화면에 필요한 주문 정보가 표시되도록 한다.

## 4단계 테스트 명세

### 기존 테스트 회귀 확인

- 기존에 작성한 테스트가 모두 통과한다.
- 상품 목록, 상품 상세, 장바구니, 상품 추천 관련 기존 기능이 깨지지 않는다.
- 기존 Navigation 동작이 깨지지 않는다.
- 기존 Flow 상태 관리 및 단발성 이벤트 처리가 깨지지 않는다.

### 결제 화면 진입 흐름 검증

- 장바구니에서 주문하기를 누르면 결제 화면으로 이동한다.
- 결제 화면에서 뒤로 가기를 누르면 이전 화면으로 이동한다.


### 쿠폰 할인 계산 검증

- `FIXED5000` 쿠폰은 주문 금액이 100,000원 이상일 때 5,000원을 할인한다.
- `FIXED5000` 쿠폰은 주문 금액이 100,000원 미만이면 적용되지 않는다.
- `BOGO` 쿠폰은 동일 상품 3개 이상 구매 시 1개 금액을 할인한다.
- `BOGO` 쿠폰은 조건을 만족하는 상품이 여러 개일 때 가장 비싼 상품 기준으로 할인한다.
- `FREESHIPPING` 쿠폰은 주문 금액이 50,000원 이상일 때 배송비를 0원으로 계산한다.
- `FREESHIPPING` 쿠폰은 도서 및 산간 지역인 경우에도 배송비를 0원으로 계산한다.
- `MIRACLESALE` 쿠폰은 오전 4시 이상 오전 7시 이전에만 30% 할인을 적용한다.
- 쿠폰 할인 금액은 주문 금액을 초과하지 않는다.
- 쿠폰 적용 후 총 결제 금액이 올바르게 계산된다.

### 최종 주문 완료 검증

- 결제하기 버튼을 누르면 최종 주문 요청이 실행된다.
- 주문 완료 성공 시 장바구니가 비워진다.
- 주문 완료 성공 시 상품 목록 화면으로 이동한다.
- 주문 완료 후 뒤로 가기를 눌러도 결제 화면으로 돌아가지 않는다.
- 주문 완료 후 쿠폰 목록은 유지된다.
- 주문 실패 시 오류 메시지를 표시한다.

### 미결제 알림 설정 검증

- 알림 설정을 On으로 변경하면 `SharedPreferences`에 `true`가 저장된다.
- 알림 설정을 Off로 변경하면 `SharedPreferences`에 `false`가 저장된다.
- 앱을 재실행해도 마지막 알림 설정값이 유지된다.
- 알림 설정이 Off이면 결제 화면 진입 시 알림 예약을 요청하지 않는다.

### 미결제 알림 예약 및 취소 검증

- 결제 화면 진입 시 알림 설정이 On이면 5분 후 알림이 예약된다.
- 결제 완료 시 예약된 알림이 취소된다.
- 사용자가 결제 화면으로 돌아오면 예약된 알림이 취소된다.
- 결제 화면 재진입 시 중복 예약이 발생하지 않는다.
- `BroadcastReceiver`가 알람을 수신하면 미결제 알림을 노출한다.

### 알림 클릭 이동 검증

- 미결제 알림을 클릭하면 앱이 실행되고 결제 화면이 표시된다.
- 알림 클릭으로 진입한 결제 화면에서 쿠폰과 주문 요약 정보가 표시된다.
- 알림 클릭 후 결제 완료 시 상품 목록으로 이동한다.
- 알림 클릭 후 결제 완료 시 장바구니가 비워진다.

## 🚀 3단계 - Navigation & Flow

## 3단계 기능 및 작업 명세

### Compose Navigation 전환

- `navigation-compose`를 사용해 단일 Activity 기반 화면 전환 구조를 구성한다.
- 기존 Activity 전환 방식을 제거하고 Compose Navigation으로 대체한다.
- 상품 목록, 상품 상세, 장바구니, 상품 추천 화면을 Navigation Component의 목적지로 등록한다.
- 각 화면 이동은 `NavController`를 통해 처리한다.

### 타입 안전 Route 구현

- 모든 Route를 `@Serializable` 타입으로 선언한다.
- 화면 이동 시 필요한 데이터는 문자열 경로 조합이 아닌 타입 안전한 Route로 전달한다.
- 상품 상세 화면 이동에 필요한 상품 식별자를 Route 데이터로 전달한다.
- 상품 추천 화면 이동에 필요한 진입 정보를 Route 데이터로 전달한다.

### 화면별 이동 콜백 분리

- 화면 Composable에 `NavController`를 직접 전달하지 않는다.
- 상품 목록 화면은 상품 상세, 장바구니, 상품 추천 화면 이동을 콜백 람다로 요청한다.
- 상품 상세 화면은 뒤로 가기와 장바구니 담기 이후 필요한 이동을 콜백 람다로 요청한다.
- 장바구니 화면은 주문 완료, 상품 목록 복귀, 추천 상품 상세 이동을 콜백 람다로 요청한다.
- 상품 추천 화면은 추천 상품 상세 이동과 이전 화면 복귀를 콜백 람다로 요청한다.

### 주문 완료 후 Back Stack 정리

- 주문 완료 후 상품 목록 화면으로 이동한다.
- 상품 목록으로 이동할 때 주문 흐름이 Back Stack에 남지 않도록 `popUpTo` 또는 동등한 Navigation 옵션을 적용한다.
- 주문 완료 이후 뒤로 가기 시 장바구니 또는 주문 흐름으로 되돌아가지 않도록 한다.

### UI 상태 StateFlow 전환

- ViewModel의 UI 상태를 `MutableStateFlow`로 관리한다.
- 외부에는 변경 불가능한 `StateFlow`로 UI 상태를 노출한다.
- 기존 `remember`/`mutableStateOf` 기반 화면 상태를 ViewModel의 `StateFlow` 상태로 이전한다.
- 상품 목록, 상품 상세, 장바구니, 상품 추천 화면의 로딩/성공/오류 상태를 Flow 기반으로 표현한다.

### 단발성 이벤트 SharedFlow 처리

- 장바구니 담기 성공, 삭제 성공, 실패 메시지 등 일회성 이벤트를 `MutableSharedFlow`로 발행한다.
- 외부에는 변경 불가능한 `SharedFlow`로 이벤트를 노출한다.
- 스낵바 표시, 화면 이동 트리거처럼 한 번만 소비되어야 하는 동작을 SharedFlow로 처리한다.
- 상태 값으로 이벤트를 보관해 재구성 시 중복 실행되는 문제를 방지한다.

### Lifecycle-aware 상태 구독

- Composable에서 `collectAsState()` 대신 `collectAsStateWithLifecycle()`을 사용한다.
- 화면별 UI 상태는 Lifecycle을 고려해 수집한다.
- SharedFlow 이벤트는 `LaunchedEffect`에서 수집하고 Composable 재구성 시 중복 수집되지 않도록 한다.

## 3단계 테스트 명세

### 기존 테스트 회귀 확인

- 기존에 작성된 단위 테스트가 모두 통과한다.
- 상품 목록, 상품 상세, 장바구니, 상품 추천 관련 기존 기능이 깨지지 않는다.

### Navigation 동작 검증

- 상품 목록에서 상품을 선택하면 상품 상세 화면으로 이동한다.
- 상품 목록에서 장바구니 화면으로 이동할 수 있다.
- 장바구니에서 상품 추천 화면으로 이동할 수 있다.
- 추천 상품을 선택하면 상품 상세 화면으로 이동한다.
- 주문 완료 후 상품 목록으로 이동하며 주문 흐름이 Back Stack에 남지 않는다.

### Flow 상태 관리 검증

- ViewModel의 UI 상태가 `StateFlow`로 노출된다.
- 장바구니 담기/삭제 등 일회성 이벤트가 `SharedFlow`로 발행된다.
- Composable이 `collectAsStateWithLifecycle()`로 상태를 구독한다.
- 화면 재구성 후에도 스낵바나 화면 이동 이벤트가 중복 실행되지 않는다.
